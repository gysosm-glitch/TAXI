# 쉐어택 발표 PPT 디자인 브리프 (v3 목표)

> 다음 작업자(사람·AI)가 이 문서만 보고 `presentation/build_v3.js`(최종본)를 고친다. 내용·숫자는 [PPT_구성안.md](PPT_구성안.md)·[자료_출처_정리.md](자료_출처_정리.md) 기준, 지어내지 않는다.

## 목표
- 2025 수상작(Trip Talk 대상, 스모크칩·이음·비콘 최우수)보다 **내용은 충실하게, 디자인은 더 세련되게**
- **교수님은 한 장을 3~5초 본다** → 장마다 **"이것만 봐도 이해되는 한 줄(핵심 메시지 박스)"**을 가장 크게
- 'AI가 만든 티'를 없앤다: 이모지 남발·둥근 그림자 카드 반복·가운데 정렬 금지

## 장마다 지킬 규칙
1. **맨 위 왼쪽 큰 결론 문장**(30pt, 문장형) → 그 아래 근거(숫자·도표) → 맨 아래 작은 보충
2. **큰 숫자 1개**를 장의 시선 시작점으로 (예: 35%, 46.5%, +5,774원, 63%)
3. 색 규칙: 진초록 `#0F2A22` 바탕/제목, 초록 `#1D9E75` = 좋은 것·쉐어택, 호박 `#F2A93B` = 문제·할증, 회색 = 비교 대상
4. 글자 최소 12pt(프로젝터), 제목 30pt, 핵심 메시지 18~20pt 굵게
5. 이모지는 장당 2~3개 이하, 아이콘처럼 한 위치에만
6. 출처·가상 인물 표기는 슬라이드에서 빼고 발표자 노트·문서에 둔다
7. 페르소나는 **팀원들이 직접 겪은 할증 부담**으로 서술

## 장별 '3초 메시지' (가장 크게)
| 장 | 3초 메시지 |
|---|---|
| 1 | 같은 청주인데 읍·면만 가면 35% 더 낸다 |
| 2 | 손님은 할증을, 기사는 빈 차 귀로를 — 같은 길에서 둘 다 손해 |
| 3 | 할증이 가장 많이 붙는 곳이, 빈 차 위험은 가장 낮다 |
| 4 | 손님·기사 모두 이득이라 지속된다 |
| 5 | 택시 앱을 대신하지 않는다 — 할증 없이 가는 3가지 길을 더한다 |
| 6 | 시 재정 0원으로 손님 이득·기사 손해 0 |
| 7 | 시민 63%가 할증 때문에 택시를 포기했다 · 참여 기사 하루 +5,774원 |
| 8 | 오송역 한 곳에서 시작해 할증 면제 고시까지 |

## 내용 보강할 곳
- 3장: 9/28 개편이 '같은 읍·면 안'만 풀어 시내↔오송·오창은 그대로라는 한계
- 5장: 앱 실제 흐름 3단계(출발·도착 검색 → 할증 없이 가기 → 모집·참여)
- 7장: 설문 57명(63·74·93·96%)을 원그래프·막대로 시각화
- 8장: 시범 운영 목표 KPI(예: 오송역 월 ○건 매칭 — 숫자는 팀이 정함), 기대 효과 수치

## 디자인 도구 사용 순서
`design:ux-copy`(문구) → 생성 → `design:design-critique`(이미지 비평) → 수정 → `design:accessibility-review`(대비) → 최종
